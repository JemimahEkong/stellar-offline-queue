# ADR-0010: V1 Numeric Defaults

**Status:** Accepted (proposed)
**Date:** September 5, 2026
**Resolves:** Open question 1 in `docs/architecture.md` §15 ("Defaults: `maxAgeSeconds` = 300, `maxAttempts` = 5, `leaseMs` = 60000 — confirm as testnet-first defaults"), extended to every numeric default the V1 implementation requires.

## Context

The architecture fixes the _mechanisms_ (exponential backoff with full jitter, lease-based claims, relative time bounds) but leaves the _numbers_ to V1 configuration. Numeric defaults in a money-moving library are policy, not taste: each one trades off settlement latency, duplicate-payment risk, fee bleed, and operational noise. The instruction for this phase is that no default may be chosen without documenting its reasoning, trade-off, configurability, and what changing it would cost.

One default (`start()` polling interval) is named in the public API but never assigned a value anywhere; the reconciliation batch limit is an implementation constant rather than public config in V1. Both are resolved here so implementers never guess.

## Principles used to choose

1. **Safety over throughput.** Where a faster number increases double-payment risk or fee bleed, choose the slower/safer number.
2. **Testnet-first ergonomics.** V1's first audience runs on testnet; defaults must make the happy path work with zero configuration while remaining production-honest.
3. **Ledger time, not device time,** for anything Stellar-correct; device-time defaults only govern _scheduling_ (`nextAttemptAt`, `start()` cadence), never validity.
4. **Defaults are frozen for the 1.x line.** Every entry below is a constructor/config default or documented constant. Changing a default after 1.0 changes observable timing/behaviour for unconfigured applications — it is treated as a **breaking change** and lands only in a major version (2.0), with the old value documented in release notes.

Formulas already fixed by architecture (repeated here for implementer convenience, values above only):

- Backoff: `delay = min(capMs, baseMs * 2^backoffAttempts) * random(0,1)` (full jitter, §6.6).
- Claim lease: `claimExpiresAt = now + leaseMs` at `claim()`; refreshed by every persisted transition (§6.7).
- Envelope bounds: `maxTime = flushTime + maxAgeSeconds` (ledger time used for verdicts, never device time).

## Consequences

- An application can construct the queue with **zero numeric configuration** and get safe, documented behaviour: 60 s leases, 5 attempts, 5-minute envelopes, 1 s→60 s jittered backoff, 5 s `start()` cadence.
- Every number above is overridable at construction (except the two internal constants), so operators tune latency vs. load without forking.
- Defaults are **frozen for 1.x**: changing any default is a major-version (2.0) change; adding new config keys is additive and non-breaking.
- The two internal constants (#8, #10) are named in code (`RECONCILE_BATCH_LIMIT`, `DUE_SCAN_PAGE_SIZE`) with references back to this ADR, so they are discoverable rather than magical.
